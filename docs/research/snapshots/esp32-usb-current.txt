<h1>USB Device Stack<a class="headerlink" href="#usb-device-stack" title="Permalink to this heading"></a></h1>
<section id="overview">
<h2>Overview<a class="headerlink" href="#overview" title="Permalink to this heading"></a></h2>
<p>The ESP-IDF USB Device Stack (hereinafter referred to as the Device Stack) enables USB Device support on ESP32-S3. By using the Device Stack, ESP32-S3 can be programmed with any well defined USB device functions (e.g., keyboard, mouse, camera), a custom function (aka vendor-specific class), or a combination of those functions (aka a composite device).</p>
<p>The Device Stack is built around the TinyUSB stack, but extends TinyUSB with some minor features and modifications for better integration with ESP-IDF. The Device stack is distributed as a managed component via the <a class="reference external" href="https://components.espressif.com/components/espressif/esp_tinyusb">ESP Component Registry</a>.</p>
</section>
<section id="features">
<h2>Features<a class="headerlink" href="#features" title="Permalink to this heading"></a></h2>
<p><ul class="simple">
<li><dl class="simple">
<dt>1 USB Full-Speed (USB 1.1) peripheral with internal PHY</dt><dd><ul>
<li><p>Endpoint 0 and 6 additional endpoints configurable as IN or OUT</p></li>
<li><p>Up to 5 IN endpoints (including Endpoint 0) concurrently active.</p></li>
</ul>
</dd>
</dl>
</li>
<li><p>Multiple supported device classes (CDC, HID, MIDI, MSC…)</p></li>
<li><p>Vendor specific class</p></li>
<li><p>Composite devices</p></li>
<li><p>VBUS monitoring for self-powered devices</p></li>
<li><p>Remote wakeup</p></li>
<li><p>Automatic light sleep control via ESP-IDF PM locks</p></li>
</ul>
</p>
</section>
<section id="hardware-connection">
<h2>Hardware Connection<a class="headerlink" href="#hardware-connection" title="Permalink to this heading"></a></h2>
<p>The ESP32-S3 routes the <strong>USB 1.1 peripheral</strong> D+ and D- signals to GPIOs 20 and 19 respectively. For USB device functionality, these GPIOs must be connected to the bus (e.g., via a Micro-B port, USB-C port, or directly to standard-A plug).</p>
<figure class="align-center">
<img alt="Connection of an USB GPIOs directly to a USB standard-A plug" src="_images/usb-board-connection.png" />
</figure>
<div class="admonition note">
<p class="admonition-title">Note</p>
<p>If you are using an ESP32-S3 development board with two USB ports, the port labeled “USB” will already be connected to the D+ and D- GPIOs.</p>
</div>
<div class="admonition note">
<p class="admonition-title">Note</p>
<p>Self-powered devices must also connect VBUS through a voltage divider or comparator. For more details, please refer to <a class="reference internal" href="#self-powered-device"><span class="std std-ref">Self-Powered Device</span></a>.</p>
</div>
</section>
<section id="external-phy-configuration">
<h2>External PHY Configuration<a class="headerlink" href="#external-phy-configuration" title="Permalink to this heading"></a></h2>
<p>The ESP32-S3 contains two USB controllers: USB-OTG and USB-Serial-JTAG. However, both controllers share a <strong>single PHY</strong>, which means only one can operate at a time. To use USB Device functionality while the USB-Serial-JTAG is active (e.g., for debugging or flashing), an <strong>external PHY</strong> is required, since the PHY is used by USB-Serial-JTAG.</p>
<div class="admonition note">
<p class="admonition-title">Note</p>
<p>An external PHY is not the only way to enable debugging alongside USB Host or Device functionality. It is also possible to switch the debugging interface from USB-Serial-JTAG to plain JTAG by burning the appropriate eFuses. For details, refer to document <a class="reference external" href="https://docs.espressif.com/projects/esp-idf/en/stable/esp32s3/api-guides/jtag-debugging/index.html">JTAG Debugging</a> in ESP-IDF Programming Guide for your target.</p>
</div>
<p>ESP32-S3 supports connecting external PHY ICs. This becomes especially relevant when full-speed USB device functionality is needed while the USB-Serial-JTAG controller is also in use. Various external PHY ICs may require different hardware modifications. Please refer to each IC’s datasheet for specifics. A general connection diagram below is provided for reference. For more information, please refer to <a class="reference external" href="https://docs.espressif.com/projects/esp-iot-solution/en/latest/usb/usb_overview/usb_phy.html#use-an-external-phy">Use an external PHY</a>.</p>
<figure class="align-center" id="id71">
<img alt="usb_fs_phy_sp5301" src="_images/usb_fs_phy_sp5301.png" />
<figcaption>
<p><span class="caption-text">A typical circuit diagram for an external PHY</span><a class="headerlink" href="#id71" title="Permalink to this image"></a></p>
</figcaption>
</figure>
<p><strong>List of Tested External PHY ICs:</strong></p>
<ul class="simple">
<li><p><strong>SP5301</strong> — Directly supported by ESP32-S3. See the guide above for schematic and routing information.</p></li>
<li><p><strong>TUSB1106</strong> — Directly supported by ESP32-S3. Works with the external-PHY driver via GPIO mapping. Follow the reference wiring in the TUSB1106 datasheet (power-supply options and recommended series resistors on D+/D–).</p></li>
<li><p><strong>STUSB03E</strong> — Requires signal routing using an analog switch. See example below.</p></li>
</ul>
<figure class="align-center" id="id72">
<img alt="External PHY with Analog Switch Schematic (Device mode)" src="_images/ext_phy_schematic_stusb03e.png" />
<figcaption>
<p><span class="caption-text">Example connection using STUSB03E and analog switch (Device mode)</span><a class="headerlink" href="#id72" title="Permalink to this image"></a></p>
</figcaption>
</figure>
<div class="admonition note">
<p class="admonition-title">Note</p>
<p>This schematic is a minimal example intended only to demonstrate the external PHY connection. It omits other essential components and signals (e.g., VCC, GND, RESET) required for a complete, functional ESP32-S3 design.
The schematic includes both a +5 V rail (usually from USB VBUS) and a VCC rail. VCC should match the chip supply voltage (usually 3.3 V). Ensure that the external PHY and the chip are powered from the same voltage domain. If designing a self-powered USB device, connect VBUSDET signal from the external PHY to ESP32-S3 for mandatory VBUS monitoring.</p>
</div>
<p>Hardware configuration is handled via GPIO mapping to the PHY’s pins. Any unused pins (e.g., <code class="xref cpp cpp-member docutils literal notranslate"><span class="pre">usb_phy_ext_io_conf_t::suspend_n_io_num</span></code>, <code class="xref cpp cpp-member docutils literal notranslate"><span class="pre">usb_phy_ext_io_conf_t::fs_edge_sel_io_num</span></code>) <strong>must be set to -1</strong>.</p>
<div class="admonition note">
<p class="admonition-title">Note</p>
<p>The <code class="xref cpp cpp-member docutils literal notranslate"><span class="pre">usb_phy_ext_io_conf_t::suspend_n_io_num</span></code> pin is <strong>currently not supported</strong> and does not need to be connected.
The <code class="xref cpp cpp-member docutils literal notranslate"><span class="pre">usb_phy_ext_io_conf_t::fs_edge_sel_io_num</span></code> pin is optional and only required if switching between low-speed and full-speed modes is needed.</p>
</div>
<p>Starting from version 2.0, the ESP TinyUSB Device Stack supports external PHY usage. To use an external PHY in device mode:</p>
<ol class="arabic simple">
<li><p>Configure the GPIO mapping and PHY using <code class="xref cpp cpp-type docutils literal notranslate"><span class="pre">usb_phy_config_t</span></code>.</p></li>
<li><p>Create the PHY using <code class="xref cpp cpp-func docutils literal notranslate"><span class="pre">usb_new_phy()</span></code>.</p></li>
<li><p>Use <code class="xref cpp cpp-func docutils literal notranslate"><span class="pre">TINYUSB_DEFAULT_CONFIG()</span></code> to initialize <a class="reference internal" href="#_CPPv416tinyusb_config_t" title="tinyusb_config_t"><code class="xref cpp cpp-type docutils literal notranslate"><span class="pre">tinyusb_config_t</span></code></a>.</p></li>
<li><p>Set the <cite>phy.skip_setup</cite> field of <a class="reference internal" href="#_CPPv416tinyusb_config_t" title="tinyusb_config_t"><code class="xref cpp cpp-type docutils literal notranslate"><span class="pre">tinyusb_config_t</span></code></a> to <code class="docutils literal notranslate"><span class="pre">true</span></code> to bypass PHY reinitialization and use the externally configured PHY.</p></li>
</ol>

<p>The basis of the Device Stack is TinyUSB, where the Device Stack implements the following features on top of TinyUSB:</p>

</ul>

<section id="self-powered-device">
<span id="id1"></span><h2>Self-Powered Device<a class="headerlink" href="#self-powered-device" title="Permalink to this heading"></a></h2>
<p>USB specification mandates self-powered devices to monitor voltage levels on USB’s VBUS signal. As opposed to bus-powered devices, a self-powered device can be fully functional even without a USB connection. The self-powered device detects connection and disconnection events by monitoring the VBUS voltage level. VBUS is considered valid if it rises above 4.75 V and invalid if it falls below 4.35 V.</p>
<p>On the ESP32-S3, this will require using a GPIO to act as a voltage sensing pin to detect when VBUS goes above/below the prescribed thresholds. However, ESP32-S3 pins are 3.3 V tolerant. Thus, even if VBUS rises/falls above/below the thresholds mentioned above, it would still appear as a logic HIGH to the ESP32-S3. Thus, in order to detect the VBUS valid condition, users can do one of the following:</p>
<ul class="simple">
<li><p>Connect VBUS to a voltage comparator chip/circuit that detects the thresholds described above (i.e., 4.35 V and 4.75 V), and outputs a 3.3 V logic level to the ESP32-S3 indicating whether VBUS is valid or not.</p></li>
<li><p>Use a resistor voltage divider that outputs (0.75 x Vdd) if VBUS is 4.4 V (see figure below).</p></li>
</ul>
<div class="admonition note">
<p class="admonition-title">Note</p>
<p>In either case, the voltage on the sensing pin must be logic low within 3 ms after the device is unplugged from the USB host.</p>
</div>
<figure class="align-center" id="id73">
<img alt="Simple voltage divider for VBUS monitoring" src="_images/usb_vbus_voltage_monitor.png" />
<figcaption>
<p><span class="caption-text">Simple voltage divider for VBUS monitoring</span><a class="headerlink" href="#id73" title="Permalink to this image"></a></p>
</figcaption>
</figure>
<p>To use this feature, set <a class="reference internal" href="#_CPPv4N20tinyusb_phy_config_t12self_poweredE" title="tinyusb_phy_config_t::self_powered"><code class="xref cpp cpp-member docutils literal notranslate"><span class="pre">tinyusb_phy_config_t::self_powered</span></code></a> to <code class="docutils literal notranslate"><span class="pre">true</span></code> and <a class="reference internal" href="#_CPPv4N20tinyusb_phy_config_t15vbus_monitor_ioE" title="tinyusb_phy_config_t::vbus_monitor_io"><code class="xref cpp cpp-member docutils literal notranslate"><span class="pre">tinyusb_phy_config_t::vbus_monitor_io</span></code></a> to the GPIO used for VBUS monitoring through <a class="reference internal" href="#_CPPv4N16tinyusb_config_t3phyE" title="tinyusb_config_t::phy"><code class="xref cpp cpp-member docutils literal notranslate"><span class="pre">tinyusb_config_t::phy</span></code></a>.</p>

<section id="power-management">
<h2>Power Management<a class="headerlink" href="#power-management" title="Permalink to this heading"></a></h2>
<section id="suspend-and-resume-events">
<h3>Suspend and Resume Events<a class="headerlink" href="#suspend-and-resume-events" title="Permalink to this heading"></a></h3>
<p>Suspend and resume device events are optional and disabled by default. Enable the following Kconfig options to receive them through the USB Device Event callback (<a class="reference internal" href="#_CPPv4N16tinyusb_config_t8event_cbE" title="tinyusb_config_t::event_cb"><code class="xref cpp cpp-member docutils literal notranslate"><span class="pre">tinyusb_config_t::event_cb</span></code></a>):</p>
<ul class="simple">
<li><p><a class="reference internal" href="#config-tinyusb-suspend-callback"><span class="std std-ref">CONFIG_TINYUSB_SUSPEND_CALLBACK</span></a> enables <a class="reference internal" href="#_CPPv4N18tinyusb_event_id_t23TINYUSB_EVENT_SUSPENDEDE" title="tinyusb_event_id_t::TINYUSB_EVENT_SUSPENDED"><code class="xref cpp cpp-enumerator docutils literal notranslate"><span class="pre">TINYUSB_EVENT_SUSPENDED</span></code></a></p></li>
<li><p><a class="reference internal" href="#config-tinyusb-resume-callback"><span class="std std-ref">CONFIG_TINYUSB_RESUME_CALLBACK</span></a> enables <a class="reference internal" href="#_CPPv4N18tinyusb_event_id_t21TINYUSB_EVENT_RESUMEDE" title="tinyusb_event_id_t::TINYUSB_EVENT_RESUMED"><code class="xref cpp cpp-enumerator docutils literal notranslate"><span class="pre">TINYUSB_EVENT_RESUMED</span></code></a></p></li>
</ul>
<p>When these options are enabled, esp_tinyusb provides strong implementations of <code class="xref cpp cpp-func docutils literal notranslate"><span class="pre">tud_suspend_cb()</span></code> and <code class="xref cpp cpp-func docutils literal notranslate"><span class="pre">tud_resume_cb()</span></code>. User applications <strong>must not</strong> define these callbacks themselves, or a linker error will occur due to multiple definitions.</p>
<p>If the Kconfig options are disabled, users may implement <code class="xref cpp cpp-func docutils literal notranslate"><span class="pre">tud_suspend_cb()</span></code> and <code class="xref cpp cpp-func docutils literal notranslate"><span class="pre">tud_resume_cb()</span></code> directly in the application instead.</p>
</section>
<section id="remote-wakeup">
<h3>Remote Wakeup<a class="headerlink" href="#remote-wakeup" title="Permalink to this heading"></a></h3>
<p>When the host suspends the device and enables remote wakeup, the device can signal resume with <a class="reference internal" href="#_CPPv421tinyusb_remote_wakeupv" title="tinyusb_remote_wakeup"><code class="xref cpp cpp-func docutils literal notranslate"><span class="pre">tinyusb_remote_wakeup()</span></code></a>. Call this function only while the device is suspended and the host has enabled remote wakeup for the current suspend cycle.</p>
</section>
<section id="automatic-light-sleep-via-pm-locks">
<h3>Automatic Light Sleep via PM Locks<a class="headerlink" href="#automatic-light-sleep-via-pm-locks" title="Permalink to this heading"></a></h3>
<p>esp_tinyusb can manage an <a class="reference external" href="https://docs.espressif.com/projects/esp-idf/en/latest/esp32s3/api-reference/system/power_management.html#_CPPv4N18esp_pm_lock_type_t21ESP_PM_NO_LIGHT_SLEEPE" title="(in ESP-IDF Programming Guide vmaster)"><code class="xref cpp cpp-enumerator docutils literal notranslate"><span class="pre">esp_pm_lock_type_t::ESP_PM_NO_LIGHT_SLEEP</span></code></a> lock based on USB device state. While the lock is held, the SoC will not enter automatic light sleep. When the USB host suspends the bus, esp_tinyusb releases the lock so automatic light sleep can proceed.</p>
<p>Enable this feature in two steps, using Kconfig options and runtime settings:</p>
<section id="kconfig-prerequisites">
<h4>Kconfig prerequisites<a class="headerlink" href="#kconfig-prerequisites" title="Permalink to this heading"></a></h4>
<blockquote>

<section id="lock-behavior">
<h4>Lock behavior<a class="headerlink" href="#lock-behavior" title="Permalink to this heading"></a></h4>
<ul class="simple">
<li><p>On driver install, esp_tinyusb creates an <a class="reference external" href="https://docs.espressif.com/projects/esp-idf/en/latest/esp32s3/api-reference/system/power_management.html#_CPPv4N18esp_pm_lock_type_t21ESP_PM_NO_LIGHT_SLEEPE" title="(in ESP-IDF Programming Guide vmaster)"><code class="xref cpp cpp-enumerator docutils literal notranslate"><span class="pre">esp_pm_lock_type_t::ESP_PM_NO_LIGHT_SLEEP</span></code></a> lock and acquires it.</p></li>
<li><p>On <a class="reference internal" href="#_CPPv4N18tinyusb_event_id_t22TINYUSB_EVENT_ATTACHEDE" title="tinyusb_event_id_t::TINYUSB_EVENT_ATTACHED"><code class="xref cpp cpp-enumerator docutils literal notranslate"><span class="pre">TINYUSB_EVENT_ATTACHED</span></code></a>, the lock is acquired if it is not already held.</p></li>
<li><p>On <a class="reference internal" href="#_CPPv4N18tinyusb_event_id_t23TINYUSB_EVENT_SUSPENDEDE" title="tinyusb_event_id_t::TINYUSB_EVENT_SUSPENDED"><code class="xref cpp cpp-enumerator docutils literal notranslate"><span class="pre">TINYUSB_EVENT_SUSPENDED</span></code></a>, the lock is released while the device remains mounted, allowing automatic light sleep.</p></li>
<li><p>On <a class="reference internal" href="#_CPPv4N18tinyusb_event_id_t21TINYUSB_EVENT_RESUMEDE" title="tinyusb_event_id_t::TINYUSB_EVENT_RESUMED"><code class="xref cpp cpp-enumerator docutils literal notranslate"><span class="pre">TINYUSB_EVENT_RESUMED</span></code></a>, the lock is re-acquired.</p></li>
<li><p>On <a class="reference internal" href="#_CPPv4N18tinyusb_event_id_t22TINYUSB_EVENT_DETACHEDE" title="tinyusb_event_id_t::TINYUSB_EVENT_DETACHED"><code class="xref cpp cpp-enumerator docutils literal notranslate"><span class="pre">TINYUSB_EVENT_DETACHED</span></code></a>, the lock is acquired and the suspend PM state is cleared.</p></li>
<li><p><a class="reference internal" href="#_CPPv421tinyusb_remote_wakeupv" title="tinyusb_remote_wakeup"><code class="xref cpp cpp-func docutils literal notranslate"><span class="pre">tinyusb_remote_wakeup()</span></code></a> acquires the lock before signaling remote wakeup to the host.</p></li>
</ul>
<p>Suspend and Resume callbacks <a class="reference internal" href="#config-tinyusb-suspend-callback"><span class="std std-ref">CONFIG_TINYUSB_SUSPEND_CALLBACK</span></a> and <a class="reference internal" href="#config-tinyusb-resume-callback"><span class="std std-ref">CONFIG_TINYUSB_RESUME_CALLBACK</span></a> must be enabled, registered inside the esp_tinyusb, otherwise the PM module would not have information about the device being suspended or resumed.</p>
<p>Use <a class="reference internal" href="#_CPPv426tinyusb_pm_get_lock_statusPb" title="tinyusb_pm_get_lock_status"><code class="xref cpp cpp-func docutils literal notranslate"><span class="pre">tinyusb_pm_get_lock_status()</span></code></a> to query whether the PM lock is currently held.</p>
</section>
</section>
<section id="light-sleep-with-usb-wakeup">
<h3>Light Sleep with USB Wakeup<a class="headerlink" href="#light-sleep-with-usb-wakeup" title="Permalink to this heading"></a></h3>
<p>On targets with full-speed port, the USB device peripheral can <strong>NOT</strong> be used as a light sleep wake-up source due to USB PHY limitations. This feature is only supported on high-speed ports.</p>

<section id="usb-serial-console">
<h3>USB Serial Console<a class="headerlink" href="#usb-serial-console" title="Permalink to this heading"></a></h3>
<p>The USB Serial Device allows the redirection of all standard input/output streams (stdin, stdout, stderr) to USB. Thus, calling standard library input/output functions such as <code class="docutils literal notranslate"><span class="pre">printf()</span></code> will result into the data being sent/received over USB instead of UART.</p>
<p>Users should call <a class="reference internal" href="#_CPPv420tinyusb_console_initi" title="tinyusb_console_init"><code class="xref cpp cpp-func docutils literal notranslate"><span class="pre">tinyusb_console_init()</span></code></a> with the CDC interface number to switch the standard input/output streams to USB, and <a class="reference internal" href="#_CPPv422tinyusb_console_deiniti" title="tinyusb_console_deinit"><code class="xref cpp cpp-func docutils literal notranslate"><span class="pre">tinyusb_console_deinit()</span></code></a> to switch them back to UART.</p>
</section>
</section>
